# 可视化说明

这份文档说明 **每张图是什么、数据从哪来、该怎么看**，以及背后的统计方法。
目标是：看到图的人（包括半年后的自己）不需要读源码就能判断结论是否可信。

---

## 一、两类实验，两套图

| | 单次运行 | 批实验 |
|---|---|---|
| 规模 | 1 数据集 × 1 算法 | N 数据集 × M 算法 |
| 问题 | 这一次表现如何？ | 整体上哪个算法更好？ |
| 图 | 学习曲线、折间分布、ROC/PR、混淆矩阵 | 平均排名、临界差异图、胜负平、数据集×算法热力图 |

判断用哪个：想知道「某个算法在某个数据集上的行为」看左边；
想证明「我的算法比基线好」看右边。

---

## 二、单次运行的图

### 1. 学习曲线

- **横轴** 训练样本量（对数刻度），**纵轴** 0-1 损失
- **阴影** 多次试验的极差（min–max）
- **数据** `curves` 表，来自 `petal -c`

看什么：
- 曲线是否还在下降 → 继续加数据是否还有收益
- 阴影宽 → 结果对训练样本敏感，不稳定
- 两条曲线交叉 → 数据量小时 A 好、大时 B 好，结论必须说明适用的数据量

只有一次试验时阴影退化为一条线，属正常。

### 2. 折间分布（箱线图）

- **数据** `metrics` 表中 `fold >= 0` 的记录（每一折一个观测）

看什么：单看平均准确率会掩盖不稳定。两个算法均值相同、但一个箱子很扁一个很长，
显然前者可信。**论文里报告交叉验证结果时，这个图能支撑"稳定"的说法。**

### 3. ROC / PR 曲线

- **数据** `predictions` 表，需要 `--dump-predictions`
- 正类固定为类别 1；AUC 用梯形法在前端计算
- 数据超过 2 万条时服务端自动等距降采样（曲线观感几乎不变）

看什么：
- ROC 的 diagonal 是随机猜测基准
- **类别不平衡时优先看 PR**——ROC 会过于乐观

### 4. 混淆矩阵

- 行真实、列预测
- **数据** `confusion` 表

看什么：哪个类别被误判成什么。整体准确率可能掩盖"某个少数类全错"。

## 三、批实验的图（跨数据集比较）

### 为什么不能直接平均误差率

难数据集上的 0.30 可能优于简单数据集上的 0.05。把不同数据集的误差率直接平均，
结果被数据集难度主导，而不是算法好坏。

标准做法是 **Demšar (JMLR 2006)**：在每个数据集内部排名，再跨数据集取平均排名。

### 1. 平均排名

每个数据集内把 k 个算法按指标排序（并列取平均秩），再对 N 个数据集求平均。
1.0 表示在所有数据集上都最好。

### 2. 临界差异图（Critical Difference）

- 点在**上排**，位置 = 平均排名
- 粗横线在**下排**，连接**差异不显著**的算法

判定规则：两个算法的平均排名之差 **小于 CD** 则无显著差异。

CD 由 Nemenyi 后验给出：

```
CD = q_α · sqrt( k(k+1) / (6N) )
```

`q_α` 查表得到（`stats.py` 中的 `NEMENYI_Q`，α = 0.05 / 0.10，k ≤ 10）。

### 3. Friedman 检验

先问“这些算法到底有没有差别”，再做事后比较。

```
χ²_F = 12N / (k(k+1)) · ( Σ Rⱼ² − k(k+1)²/4 )
```

与自由度 k−1 的 χ² 临界值比较。

> **重要**：Friedman 检验功效随 N 增长。N 很小时（比如 4 个数据集）几乎不可能显著，
> 此时的"无显著差异"**不等于算法等价**，只能说证据不足。经验上 N ≥ 10 才比较有力。
> 界面会在 N 较小时给出这个提醒，写论文时不要漏掉。

### 4. 胜负平（Win / Draw / Loss）

两两在各数据集上比较，统计胜负平次数。比排名更直观，但没有显著性含义——
3 胜 2 负可能完全是噪声。

### 5. 数据集 × 算法热力图

暴露平均排名看不到的模式，例如「某算法在某几个数据集上崩溃」。
如果一列颜色明显异常，值得单独分析那个数据集。

## 四、导出

每张图右上角两个按钮：

| 按钮 | 说明 |
|---|---|
| **SVG** | 矢量，可无损缩放，也能用 `rsvg-convert` / Inkscape 转 PDF。投稿首选 |
| **PNG** | 4 倍缩放渲染，约合 300 dpi，适合 Word/PPT |

## 五、数据来源与已知限制

- **当前库中的数据是合成数据**（`syn_easy` / `syn_mid` / `syn_hard` / `syn_harder`，
  以不同噪声水平生成），仅用于验证流程，**不能用于任何结论**。
  真实数据到位后需 `petal-lab reset` 清空再重新导入。

- 指标方向：代码假设 **越小越好**（0-1 损失、RMSE、对数损失）。
  **AUC 是越大越好**，用它做排名会得到反向结论——这是尚未处理的已知问题。

- 训练/测试时间：petal 仅在 Linux 下计时（`#ifdef __linux__`），
  macOS 上这两个值为 0。

- ROC 的正类固定为类别 1，多分类场景目前只做该类的 one-vs-rest。

## 六、加一张新图的步骤

1. `petal_lab/stats.py`（如需要新的统计量）
2. `petal_lab/server.py` 暴露为 API
3. `lab/web/src/charts/specs.js` 写 Vega-Lite 规范
4. 在对应 view 里用 `<Chart spec={...} data={...} />`

图表规范集中在 `specs.js`，不散落在组件里，便于单独审阅和导出。
